# 每日人物分析（DeepSeek）

入口：<http://127.0.0.1:18768/daily>，或事件预览左侧“每日分析”。

## 本机配置

1. 启动原有 `ai-events/start.ps1`，进入“模型与监控位置”。
2. 填写 DeepSeek 官方 API Key；默认模型 `deepseek-flash`，Base URL `https://api.deepseek.com`。支持用户消息中的图片输入，采用 `/chat/completions` 和 JSON 输出。
3. 给每个摄像头填写实际位置，可附入口方向。摄像头名称和数量动态读取设备列表，无固定三路或通道 ID。
4. 保存后可测试已保存的接口配置；该测试只验证文本接口连通，实际图片能力需要生成一个事件分析验证。
5. 选择日期和范围，点击“生成日报”。只有生成任务或启用自动日报后才会发送事件图片，不发送音频或完整视频。

API Key 由 Windows DPAPI 使用当前 Windows 用户加密，保存于 `data/settings.private.json`。页面和 API 不会返回密钥；复制至另一电脑或用户后需重新填写。也支持进程环境变量 `DEEPSEEK_API_KEY`。配置不要公开分享。

## 分析方式

- 读取 EasyNVR 数据库中所选日期的人形事件，合并同路间隔不超过15秒的事件，前后补充5秒和10秒；每段最多120秒。
- 从已经完成的本机录像提取最多8张连续 JPEG，最长边约1280像素。录像已清理或图片不足会记录失败，不以截图冒充视频分析。
- 模型接收位置、逐帧录像时间，输出一句话、动作类型、证据图片编号、不确定性。
- 疑似摔倒额外取前后3秒、每秒2帧复核，最多13张；仅提示“疑似”，不能据此作医疗或安全判断。
- 多人面对面只能描述互动或疑似交谈；不猜测身份、关系、意图、说话内容。
- 汇总只使用成功分析的事件，保留疑似措辞，每条摘要关联有效证据编号。点击“查看对应录像”跳至原有播放器的该路、该日期、该时间。录像有空缺时沿用原播放器的最近可用片段提示。

这不是对全天录像的完整观看：未触发人形事件、漏检、录像缺失和两次采样之间的动作都可能遗漏；页面明确标注范围。当前没有对未触发时段自动巡检，也没有人工修正编辑入口。没有事件不能得出全天无人、无异常的结论。

## 任务、开销与部署

- 一个后台工作线程，避免多任务并发解码；暂停/停止不会影响原录像和目标检测。
- 默认每次最多60个片段、每天160次 API 调用，可在本机调整。失败请求也占用本地计数；达到上限后不再发送。
- 可选每天北京时间00:10生成前一天所有摄像头的日报，默认关闭。需要本机服务在运行；服务晚于00:10启动时会补前一天，不自动补全部历史日期。
- 重复任务复用相同素材、位置、模型和提示版本的逐片段结果；日报汇总仍会产生一次 API 调用。录像优化修改原文件后会重新分析。
- 任务、缓存、调用计数存 `data/analysis.db`；证据 JPEG 存 `data/evidence/`。没有复制原始 MP4；证据和日报不会自动清理，原“清空录像/事件”也不会清理独立分析证据。
- 被中断的任务重新排队并复用已完成结果；没有网络、密钥失效、额度不足会显示失败或部分完成，不生成虚构结论。
- 迁移时复制整个 `daily-analysis` 源码文件夹和更新后的 `ai-events` 三个文件。新组件仅用 Python 标准库和已有 FFmpeg，没有增加 pip 依赖；密钥需要在新机重新填写。要保留历史报告可复制 `data`，注意其包含监控图片。
