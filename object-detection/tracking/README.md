# 人物增强检测

2026-11-07。与既有YOLO26s ONNX共用一个CPU推理会话，每个通道创建独立PersonPipeline；不写固定摄像头ID，不上传图像。

## 机制

- 固定版本 `supervision==0.30.9` 中的真实ByteTrack（Kalman与高低分两阶段关联），配置需随版本验证；此版本API已标记弃用，未来升级0.31+需迁移到trackers，不能无约束升级。
- 高阈值0.5用于新目标，低阈值0.2仅参与已有轨迹关联；新目标连续两帧确认。高分但尚无稳定ID的候选仍保留旧的两次确认机制，避免稀疏取样导致识别结果被跟踪器丢掉。
- 1280×720可用源帧，最大2fps取帧，保持比例补边；全图送入640模型，局部复检直接裁剪高清帧再送模型，不从640缩略图二次放大。
- 每轮最多一次局部推理。优先复核「熊」候选框，其次检查低分人物或刚丢失人物的位置。空闲时每 2 秒轮询四块重叠区域，裁剪范围随画面尺寸计算。
- 空闲目标1fps，出现高分候选或保留人物时目标2fps；CPU不足时处理最新帧并跳过旧帧，不积压排队。实际频率可能低于目标。
- 跟踪丢失状态按主机时间最多5秒保留，处理间隔超过5秒则清空，避免直接照搬30fps默认缓冲。预测框不会作为真实命中写入事件；只有匹配到本帧检测的框才输出。
- 已有事件的短暂漏检缓冲为 5 秒。last_trigger_time 表示最后真实匹配时间，duration 可能包含缓冲。没有视频帧时停止延长事件，停用人形时清空轨迹。
- 动物候选框若与同位置的高分人物或近期确认轨迹明显重叠，会被过滤。「熊」还需在同一位置的局部画面中确认同类。车辆仍按原高阈值检测。

## 文件与参数

`settings.json` 控制启用、阈值、确认帧数、保留秒数、目标帧率与ROI间隔。修改后重启 `../start.ps1` 对应检测进程。当前取帧上限2fps；不要将active_fps配置成更高值而期待自动提高取帧上限。

生产依赖已记录在 `../requirements.txt`。Supervision在未安装OpenCV时提示NumPy后端；此方案只调用检测结构和ByteTrack关联，未使用其绘图/视频读取，测试通过。FFmpeg仍负责取帧，Pillow负责裁剪。

## 回退

将settings.json中enabled改为false，核实并结束 `../process.json` 对应的detector.py及其取帧子进程，再执行 `../start.ps1`。恢复原每秒640×360整图推理，不删除依赖或模型。更早的代码/依赖清单备份在 `../../maintenance/person-tracking-20261107/`。

## 验证

14 项检测与追踪测试通过，覆盖低分接续、轨迹超时、通道隔离、确认后写事件，以及人物与动物冲突时的复核和过滤。

08:39及08:40两段录像按每秒一帧共122帧对比：旧全图流程输出人物16帧，增强流程19帧（包含待确认高分候选），新增3帧均为确认跟踪输出，已人工查看对应图片确有人；其中一帧0.37低分接续成功。这个小样本不是准确率/召回率评测，不证明其他场景都改善。旧推理中位183.4ms，新流程中位331.6ms、均值279.1ms；有ROI的轮次更贵。详见maintenance目录 comparison.json及additional图片。
